# 数据记录格式（给记录数据的 agent）

数据跟着作品走，文件就是数据。记录数据的 agent 只做一件事：往作品文件夹里的 `数据/` 追加文件；SPT 读这些文件建索引，界面、`spt metrics`、MCP 都从索引查。原来的项目文件（CSV、复盘 md、原始快照）不动。

```
工作区/<专业>/2026-10-20-AK-定格环绕/
├── 发布记录.md                 哪天、哪个平台、哪个账号、链接（发布时间从这里来）
└── 数据/
    ├── 表现.csv                一次记录一行，只追加，不改旧行
    ├── 留存.csv                视频才有：留存曲线的点
    └── 分析/
        └── 2026-10-22-D3.md    一次分析一个文件

工作区/数据/账号/<平台>-<账号>/
├── 表现.csv                    账号级：粉丝数、当天总浏览……
└── 分析/2026-10-22-周复盘.md   账号级分析
```

`spt metrics add`、`spt metrics analyse`、`spt metrics account` 会按这个格式写文件，agent 不必自己拼 CSV；直接写文件也行，格式如下。

## 表现.csv（作品级，一次记录一行）

```csv
记录时间,平台,账号,浏览,触达,点赞,评论,收藏,分享,主页访问,涨粉,点击率,三秒率,完播率,平均观看秒,来源,备注
2026-09-10T03:35:00-07:00,rednote,示例创作者,72,,8,1,1,1,,,,,,,原始快照/2026-09-10-0335-后台与主页核验.json,
2026-09-11T21:35:00-07:00,rednote,示例创作者,82,,8,2,1,1,,,,,,,原始快照/2026-09-11-2135-后台与主页核验.json,D3 晚到 4.2 小时
```

- 第一行是表头，列名照抄；列的顺序不限，多出来的列会被忽略，少的列当空。UTF-8，逗号分隔，格里有逗号就用英文双引号包起来。
- **记录时间**：ISO 8601，带时区（`2026-10-22T09:30:00+08:00`、`…-07:00`、`…Z`）。没带时区按这台电脑的时区算。只有日期（`2026-10-22`）也收，按当天 12:00 算，D1/D3/D7 会不准。
- **平台**：`rednote`（小红书）、`douyin`、`wechat_channels`（视频号）、`bilibili`、`instagram`、`facebook`、`tiktok`、`youtube`、`google_business`、`yelp`。写中文（小红书、抖音、视频号、B站、油管）也认。
- **账号**：这个平台上的账号名，和「账号档案」、`发布记录.md` 里写的一致。一个客户在同一平台只有一个号时可以留空。
- **不知道的留空，不写 0。** 浏览不能替代触达，不要从浏览反推点击率。
- **点击率、三秒率、完播率**：百分数，`12.5` 或 `12.5%` 都行，表示 12.5%。**平均观看秒** 是秒数。
- **来源**：数字从哪来（后台页面、导出文件、快照文件名）。**备注**：补录、晚到、口径冲突等一句话。
- 只追加。记错了另加一行写清楚，不改旧行。同一时间同一平台只记一次。

D1 / D3 / D7 不用 agent 自己算：SPT 用 `发布记录.md` 里的发布时间和每行的记录时间算出每条记录距发布多少小时，取最接近 24 / 72 / 168 小时的一条当节点（允许范围 D1 18–48 小时、D3 48–120 小时、D7 120–240 小时），并显示晚到多少小时。没有发布时间就只有时间线，没有节点。

## 留存.csv（视频才有）

```csv
记录时间,平台,账号,秒,留存率
2026-10-22T09:30:00+08:00,rednote,示例创作者,0,100
2026-10-22T09:30:00+08:00,rednote,示例创作者,3,71.5
2026-10-22T09:30:00+08:00,rednote,示例创作者,10,40
```

同一次读到的曲线用同一个记录时间，一行一个点；留存率是百分数。SPT 画最近一次的曲线。

## 分析/（一次分析一个文件）

文件名 `日期-节点.md` 或 `日期-主题.md`。开头几行是固定的「键: 值」，空一行后正文随便写（现象、原因、下次怎么改）：

```markdown
平台: rednote
账号: 示例创作者
节点: D3
结论: 开头 3 秒没有冲突，封面和标题重复
标签: 开头弱, 封面

## 现象
前 3 秒留存从 100 掉到 58……

## 下次怎么改
……
```

- 用 `---` 把头几行包起来也行。`平台`、`节点`、`结论` 尽量写；`账号` 一个号时可不写；`日期` 不写就用文件名里的日期。
- **节点**：`D1`、`D3`、`D7`、`周`、`复盘`……随便写，界面原样显示。
- **标签** 是「毛病」的名字，用逗号或顿号分开，同一个毛病每次写同一个词，SPT 才能按标签统计哪些毛病最常见：`开头弱`、`封面`、`标题`、`节奏慢`、`选题偏`、`结尾无引导`、`发布时间`、`话题标签`。新词可以加，加了就一直用。
- **结论** 一句话，列表里就显示这一句。

## 账号级（工作区/数据/账号/）

文件夹名 `<平台>-<账号>`，例如 `rednote-示例创作者`。里面 `表现.csv`：

```csv
记录时间,粉丝,浏览,触达,互动,点赞,评论,收藏,分享,主页访问,涨粉,来源,备注
2026-10-21T03:48:26-07:00,200,,,,,,,,,,公开主页,
```

`分析/` 的格式和作品级一样（不用写 `平台`、`账号`）。

## 查

```sh
spt/bin/spt metrics --client 示例创作者 --platform rednote          # 一行一篇：最新、D1/D3/D7、完播率、标签
spt/bin/spt metrics --tag 开头弱                                    # 带这个毛病的都有哪些篇
spt/bin/spt metrics tags --client 示例客户                                # 哪些毛病最常见
spt/bin/spt metrics show 2026-09-08-示例创作者-小车先停好             # 一篇的时间线、留存、分析
spt/bin/spt metrics --since 2026-10-01 --json                       # 给 agent 用的 JSON
```

MCP 对应 `spt_metrics`（查）、`spt_metrics_add`（记一行）、`spt_metrics_analyse`（写一份分析）。

## 记

```sh
spt/bin/spt metrics add --work 2026-09-08-示例创作者-小车先停好 --platform rednote --account 示例创作者 \
  --at 2026-10-22T09:30:00+08:00 --views 92 --likes 8 --comments 2 --saves 1 --shares 1 \
  --source 后台已发布列表 --note "D7 晚到 5.6 小时"
spt/bin/spt metrics retention --work … --platform rednote --points "0:100,3:71.5,10:40"
spt/bin/spt metrics analyse --work … --platform rednote --node D3 --conclusion "开头 3 秒没有冲突" \
  --tags "开头弱, 封面" --file 分析正文.md
spt/bin/spt metrics account --platform rednote --account 示例创作者 --followers 200 --source 公开主页
```

`--work` 收作品 id 或文件夹名（唯一匹配的关键字也行）。写完自动刷新索引。

## 读数据（小红书，Mac 上的 SPT 自己读）

小红书的数字由 Mac 上的 SPT 应用用本机的登录去读，不用别人远程登录：

- 什么时候读：SPT 应用开着时每 8 小时自己读一次（上次没读成的话 2 小时后再试）；「数据」页右上角「读数据」随时读一次；agent 用 `spt/bin/spt metrics capture`（读完才返回，`--status` 只看上次结果，`--json` 给 agent）。
- 读什么：每个在 SPT 里登录过的小红书账号，打开创作中心「笔记管理」，读最近 14 天的笔记（标题、发布时间、浏览、评论、点赞、收藏、分享，列表上就是这个顺序），再读公开主页的粉丝数。只滚动列表，不点、不填、不发。
- 记到哪：按 `发布记录.md` 里的笔记 ID 找作品，没有 ID 就按标题加发布时间（列表上的时间是北京时间）对；对上了追加一行到作品的 `数据/表现.csv`，来源写 `SPT 读数据 · 笔记管理`；粉丝数追加到 `工作区/数据/账号/rednote-<账号>/表现.csv`。对不上的笔记不新建作品，只在结果里列出来。
- 不重复：同一篇 45 分钟内读过就不再记；数字没变、上次不到 20 小时也不再记。`1.2万`、`1.7K` 这种约数不记，留空。
- 登录的不是这个账号（页头名字对不上）就整次不记；登录过期会提示去「发布 → 平台入口」重新登录。
- Windows 和浏览器里没有这一步，只能用 `spt metrics add` 记。

## 规矩

- 只追加，不改旧行、不删文件；修正另记一行并写备注。
- 不可见的字段留空；不同口径不混成一个数。
- 记录时间带时区。晚到的节点照记，SPT 自己标晚到了多久。
- 不把账号、密码、cookie、token 写进任何文件。
