# SPT 资产库 · Agent 指南

SPT 是 用户的本地资产库。作品、提示词、素材、记录、skills 都在一个文件夹里：

- 软件根目录：本文件的上一级文件夹（下文的相对路径都从这里算）
- 库根目录：`工作区/`（在软件根目录里）
- 命令：`spt/bin/spt`（在软件根目录里运行；或用完整路径）

SPT 只读文件、建索引、给界面和 agent 查询。**文件就是数据**：想新增或修改内容，就按下面的规则直接写文件，然后刷新索引。索引缓存在 `spt/server/.cache/`，可随时删掉重建。

## 三步用法

1. **先找**：做新东西前，先查有没有能用的提示词、素材和以前的作品。
   ```sh
   spt/bin/spt search 小笼包                 # 全部类型
   spt/bin/spt search 夜景 --kind material --section 场景
   spt/bin/spt search 火光 --kind prompt --all-versions   # 连作品的旧版本提示词一起
   spt/bin/spt get <id>                      # 取完整内容
   spt/bin/spt text <id>                     # 只打印提示词正文
   spt/bin/spt sections                      # 各类数量和分组
   spt/bin/spt metrics --client 示例客户           # 作品的数据记录：最新、D1/D3/D7、标签（见「数据」）
   spt/bin/spt metrics show <作品文件夹名>     # 一篇的时间线、留存、分析
   ```
   接了 MCP 的话，对应工具是 `spt_search`、`spt_get`、`spt_sections`、`spt_guide`、`spt_metrics`（`spt_search` 传 `all_versions: true` 等于 `--all-versions`）。
2. **再存**：做好的作品用 `spt add` 收进来（见下方「收录做好的作品」）；提示词、素材、记录按「目录规则」直接写文件；作品发出去以后的数据用 `spt metrics add` 记（见「数据」）。
3. **刷新**：服务在运行时，写进 `工作区/` 的文件几秒内会自动进索引；用命令行查询前运行 `spt reindex` 保险。

`--kind` 可选 `work`（作品）、`prompt`（提示词）、`material`（素材）、`record`（记录）、`note`（便签）、`skill`。

## 目录规则

```
工作区/
├── README.md                      存放说明（给人看）
├── AGENTS.md                      给 agent 的入口，指向本文件
├── 客户.md                        (可选) 客户名单：简称、名字、类型、颜色，见「客户名单」
├── SPT.yaml                       (可选) 只读收录的外部目录，见「外部来源」
├── <专业>/                        电影、运营、人像……一个专业一个文件夹
│   └── 2026-10-20-AK-五道菜轮播/  一件作品一个文件夹：日期-客户-主题
│       ├── 说明.md                (可选) 这件作品是什么，见下方格式
│       ├── 记录.md                为什么这样做、改了什么、用户怎么说、发没发
│       ├── 提示词.md              作品级提示词；多张图就 提示词-1.md、提示词-2.md
│       ├── 参考分工.md            (可选) 哪张参考图管什么；参考图-1.md 等同理
│       ├── V1/                    第一版
│       │   ├── 01_菜品.jpg        按编号顺序传进生成工具的图
│       │   ├── 正文.txt           这一版整段贴进去的提示词
│       │   ├── 参考_原片.mp4      参考_ 开头：只看不传
│       │   └── 回片1.mp4          生成好下载回来的结果
│       ├── V2/                    用户说不对、改写提示词才开；V1 原样不动
│       ├── 成片.mp4、封面.jpg     剪好要发的，放根目录
│       ├── 发布包.md、发布记录.md 发布记录里的时间就是算 D1/D3/D7 的发布时间
│       └── 数据/                  发出去以后的数据，见「数据」
│           ├── 表现.csv           一次记录一行，只追加
│           ├── 留存.csv           视频的留存曲线
│           └── 分析/2026-10-22-D3.md  一次分析一个文件
├── 提示词/<分组>/<名称>.md        可复用的提示词模板
├── 素材/<名称>.md                 素材表：每一行是一条素材
├── 素材/<分组>/<文件>             素材图片或视频；同名 .md 写说明
├── 记录/<日期-主题>.md            日常记录、复盘、学到的东西
├── 便签/<分组>/<编号>.md          SPT「便签」页的便签，见下方
├── 数据/账号/<平台>-<账号>/       账号级数据：表现.csv、分析/，见「数据」
└── skills/<名字>/SKILL.md         库内 skill
```

`素材`、`提示词`、`记录`、`便签`、`数据`、`skills` 是保留名，不要用它们当专业名。

工作区的位置可以在 SPT「设置 › 工作区」里换（存在 `spt/settings.local.json`，不随分享包带走）；命令行和 MCP 跟着用同一个位置。`spt/bin/打包分享` 做出的分享包里另有 `spt/settings.share.json`（`{"share": true}`），`/api/health` 据此报告 `share: true`，界面会隐藏只有库主人用得上的工具；自己的文件夹里没有这个文件，`share` 就是 `false`。以 `.` 开头的文件和符号链接不会被读取（skills 文件夹除外，见下文）。

## 每一类怎么写

### 作品

- 文件夹名必须是 `YYYY-MM-DD-客户-主题`。客户名里不能有 `-`；自己的作品客户写 `自家`。名字不对就不会被识别成作品。
- 每次大改开新版本 `V2/`、`V3/`，旧版本原样保留；数字最大的就是最新版。长片用 `段01/`、`段02/`。
- 卡片封面按这个顺序找：根目录的 `封面.jpg`（`封面.png` 等也行）；没有就用定稿那一版文件夹里的第一张图（没定稿就最新一版；按文件名自然顺序，01 在 10 前面）；再没有就用根目录的第一张图；都没有、但有成片视频，就抽一帧。接口里 `cover_source` 是用的那张图在作品里的路径，`cover_rule` 是用了哪条规则（`封面`、`版本图`、`根目录图`、`视频抽帧`、`spt.yaml`）。
- 提示词有两种放法，SPT 都会收进「提示词」：
  - 每个版本的 `V*/正文.txt`：这一版实际用的整段提示词
  - 作品根目录的 `提示词.md`、`提示词-1.md`……：一组多张图时一张一份
- 「提示词」列表、搜索和数量里，每件作品的 `V*/正文.txt` 只出一份，就是定稿那一版：`发布记录.md` / `发布包.md` 写了定稿是哪一版（如「当前采用：V2」）就用那一版；没写，或写的那一版文件夹不在，就用数字最大的一版。定稿那一版没有 `正文.txt` 时，不拿别的版本顶替。
  - 其他版本的提示词还在索引里，标着 `superseded: true`（列出的那一份带 `version`，是记录里写的定稿时还带 `adopted: true`）。作品详情和 `spt get <作品 id>` 里每个版本都看得到；搜索加 `--all-versions` 才一起列出。
  - `段01/`、`段02/` 是长片的几段，不是版本，每段都列；根目录的 `提示词*.md` 不分版本，一直列出。
- `说明.md` 可选，用来给作品起展示名、打标签：
  ```markdown
  ---
  标题: 五道菜轮播
  标签: 餐厅, 轮播, Instagram
  工具: 即梦 4.0
  说明: AK 菜单品牌版式，7 张 4:5
  ---
  其他补充说明写在这里。
  ```

### 客户名单（`客户.md`）

库根目录可以放一份 `客户.md`：一张 Markdown 表格，写清每个客户简称是谁、放在哪一组。资产库界面按客户分组时读它；`/api/health` 的 `clients` 就是这张表加上作品里出现过的客户，`client_groups` 是分组名（按文件里出现的先后）。

```markdown
# 客户

| 简称 | 名字 | 类型 | 颜色 |
|---|---|---|---|
| 自家 | 自家 | 自己 | |
| 示例创作者 | 示例创作者 | 自己 | #d6a4ff |
| AK | Sample Studio | 客户 | #f0b35c |
```

- `简称` 必填，就是作品文件夹名 `日期-客户-主题` 里的客户，照抄，一行一个，不能重复（不能有 `|`、`/`、`-`）。
- `名字` 可不写，默认和简称一样。`类型` 是**分组名**：`自己` 和 `客户` 是默认的两组，也可以写任何名字（如 `餐厅`、`品牌`），资产库里每组一簇，顺序照文件里出现的先后；不写就算 `客户`，`自家` 不写就算 `自己`。接口里 `kind` 只有两种：`自己` 组和 `自家` 是 `own`，其余是 `client`。`颜色` 可不写，写就用 `#rrggbb`，不合格式的会被忽略。
- 列按表头文字认，顺序随意，多出来的列不管。某一行看不懂，SPT 会在「设置 › 资产库」列出是第几行，其他行照常用。
- 作品里出现、表里没有的简称也会列出来，只是没有名字和颜色：有 `客户` 组就归 `客户`，没有就归文件里最后一组；表里没有的 `自家` 归 `自己`（没有 `自己` 组就归第一组）。遇到新客户，agent 可以直接在表末尾加一行，不用问。
- 界面的「整理客户」（改名、换颜色、挪组、改组名、加组、删掉没作品的客户）会**重写这张表**：表格前后的文字原样保留，只有表格本身按分组顺序重排；没有客户的组不会写进去。还有作品的简称删不掉。
- 这个文件不是记录，也不是专业：SPT 不会把它收进「记录」，也不会把 `客户` 当成专业名。

### 提示词模板（`提示词/`）

一份提示词一个 `.md`（或 `.txt`），按分组放子文件夹。frontmatter 可选：

```markdown
---
标题: 色面棚拍菜品底图
标签: 菜品, 棚拍, 无字底图
工具: 即梦
说明: 餐厅轮播封面，红黄色面，硬光长影
---
为餐厅 Instagram 轮播做一张……（这里就是会被一键复制的提示词正文）
```

- 不写 `标题` 时，用第一个 `#` 标题或文件名。正文开头和标题相同的 `#` 行不会被复制进去。
- 同一文件夹里放一张同名图（`色面棚拍菜品底图.jpg`），卡片上就会显示效果图。

### 素材表（`素材/<名称>.md`）

一张 Markdown 表格，每一行是一条素材。必须满足：

- 第一列叫 `编号`（如 `Y001`）
- 有一列名字里带 `写法`（如 `写法`、`即梦写法`）：这一列就是一键复制的内容

其他列可选：第二列作标题（`名称`、`类型`、`大类`、`风格`都行），`适合类型` 或 `色系` 作标签，`来源` 作说明。某一行任意格里写了 `不采用`，这条会变灰。

```markdown
# 衣服库

| 编号 | 大类 | 即梦写法 | 色系 | 用过次数 | 最近使用 | 来源 |
|---|---|---|---|---|---|---|
| Y001 | 冬日·叙事 | 奶白色粗针织毛线帽，燕麦色羊毛大衣敞开…… | 奶白+燕麦 | 0 |  | 电影节·Zero Point |
```

表格以外的 `.md`（比如 `角色.md` 这种档案）会作为一条文档素材，和同名文件夹里的图片归在同一组。

### 素材文件（`素材/<分组>/`）

图片或视频放分组文件夹，例如 `素材/角色/Kaia/kaia-真人-脸.png`。说明写在同名 `.md`（`kaia-真人-脸.md`）里，或整个文件夹共用一份 `说明.md`。格式和提示词的 frontmatter 一样。

### 记录（`记录/`）

日常记录、复盘、学到的方法，一篇一个 `.md`，文件名用 `日期-主题.md`。和某件作品有关的记录写在那件作品的 `记录.md` 里，不放这里。

### 数据（`数据/`）

作品发出去以后的数字跟着作品走，放在作品文件夹的 `数据/` 里；粉丝数这类账号级数字放 `工作区/数据/账号/<平台>-<账号>/`。完整格式见 [docs/数据记录格式.md](docs/数据记录格式.md)，要点：

- `数据/表现.csv`：一次记录一行，只追加、不改旧行。列：`记录时间,平台,账号,浏览,触达,点赞,评论,收藏,分享,主页访问,涨粉,点击率,三秒率,完播率,平均观看秒,来源,备注`，按表头认列，顺序随意，多的列不管。记录时间带时区（`2026-10-22T09:30:00+08:00`）；平台写 `rednote`、`douyin`、`wechat_channels`、`bilibili`、`instagram`、`facebook`、`tiktok`、`youtube`、`google_business`、`yelp`（小红书、抖音等中文也认）；**不知道的留空，不写 0**；百分数写 `12.5` 或 `12.5%`。
- `数据/留存.csv`：`记录时间,平台,账号,秒,留存率`，同一次读到的曲线用同一个记录时间，一行一个点。
- `数据/分析/<日期>-<节点或主题>.md`：开头几行 `平台:`、`账号:`、`节点:`、`结论:`、`标签:`（用 `---` 包起来也行），空一行后随便写。`结论` 一句话；`标签` 是毛病的名字（`开头弱`、`封面`、`标题`、`节奏慢`、`选题偏`、`结尾无引导`、`发布时间`、`话题标签`……），同一个毛病每次写同一个词。
- D1 / D3 / D7 不用自己算：SPT 用 `发布记录.md` 里的发布时间算每行距发布多少小时，取最接近 24 / 72 / 168 小时的一行当节点（D1 18–48、D3 48–120、D7 120–240 小时），并标出晚到几小时。没有发布时间就只有时间线。
- 记的时候用命令，不用自己拼 CSV（写完自动刷新索引；`--work` 收作品 id、文件夹名或唯一关键字）：
  ```sh
  spt/bin/spt metrics add --work 2026-09-08-示例创作者-小车先停好 --platform rednote --views 92 --likes 8 --source 后台已发布列表
  spt/bin/spt metrics retention --work … --platform rednote --points "0:100,3:71.5,10:40"
  spt/bin/spt metrics analyse --work … --platform rednote --node D3 --conclusion "开头 3 秒没有冲突" --tags "开头弱, 封面" --file 正文.md
  spt/bin/spt metrics account --platform rednote --account 示例创作者 --followers 200 --source 公开主页
  ```
- 查：`spt metrics`（一行一篇）、`spt metrics tags`（哪些毛病最常见）、`spt metrics show <作品>`，都可加 `--json`；MCP 是 `spt_metrics`、`spt_metrics_add`、`spt_metrics_analyse`。接口：`GET /api/metrics`、`GET /api/works/<id>/metrics`。
- 读不懂的行会跳过，并在 `/api/health` 的 `issues`（设置 › 资产库）里写明文件和第几行。
- 小红书数字由 Mac 上的 SPT 应用自己读（`spt/server/metrics_capture.py` + `native/MetricsReader.swift`）：每 8 小时一次，或「数据」页「读数据」、`spt metrics capture`。agent 要最新数字就先跑 `spt metrics capture` 再查，不要远程登录小红书去采。规则见 docs/数据记录格式.md「读数据」。

### 便签（`便签/`）

- 每个分组是 `便签/` 下的一个文件夹（如 `便签/AK/`），每张便签是 `YYYYMMDD-HHMMSS-xxxx.md`（`xxxx` 是 4 位小写字母或数字）。
- 文件开头可写颜色和日期：`---\n颜色: mint\n日期: 2026-10-28\n---`。颜色可选 lilac、mint、pink、butter、sky；日期可省略（省略时月历按文件名里的日期放）。下面就是正文，第一行当标题。
- 分组和便签的顺序记在 `便签/.布局.json`，不认识的新文件排在最后，不用改它。
- 撤下的便签移到 `便签/.已撤下/`，不要删除文件。真要删，用界面的删除（进系统废纸篓）；「清空已撤下」也是整组移进废纸篓。
- 和 用户 确认过的待办、客户的原话、下次要注意的事，直接写成一张便签（有日期就写 `日期:`）。他在「便签」页和「运营」右栏看到的就是这些文件。

### Skills

- 库内 skill：`skills/<名字>/SKILL.md`，开头写 frontmatter：`name`、`description`。
- Claude（`~/.claude/skills`）和 Codex（`~/.codex/skills`）里你自己装的 skill 会被自动读进来，**不要移动或复制它们**，移走会让 agent 找不到。它们自带的（Codex 的 `.system/`、Claude 应用同步来的 Anthropic skills）不收录。
- 想让库内 skill 也被 Claude 或 Codex 使用：在 `~/.claude/skills/` 里放一个指向它的符号链接，不要复制。
- 本软件自带的 skill 在 `spt/skills/spt-library/`。

### 外部来源（`SPT.yaml`）

不想搬、但想在 SPT 里看到的目录（比如另一个笔记库里的方法和提示词），写进库根目录的 `SPT.yaml`。SPT 只读这些目录里的文字文件，不移动、不复制、不改写：

```yaml
skills:                       # 读每个子文件夹的 SKILL.md
  - 名称: 我的方法库
    路径: ~/Documents/方法库/skills
    提示词: true              # 同时把每个 skill 里 prompts/ 的文件收进「提示词」
prompts:                      # 读 .md / .txt，按子文件夹分组
  - 名称: 运营
    路径: ~/Documents/方法库/运营提示词
records:
  - 名称: 周报
    路径: ~/Documents/周报
```

路径里只要有 `账号`、`accounts`、`.git`、`.env`、`node_modules` 这些名字，SPT 一律不读。外部来源不显示图片预览；要预览的素材请放进 `素材/`。

## 收录做好的作品（`spt add`）

作品做完、要交付或已发布时，用一条命令把它收进工作区。它会按上面的规则建好 `<专业>/<日期-客户-主题>/`，**只新增文件**：不覆盖、不删除、不动原件；同名但内容不同的文件两边都留（新的叫 `xxx-收录2`）；视频和图片用 APFS 克隆，不多占硬盘。账号、cookie、token 之类的文件一律跳过。

```sh
spt/bin/spt add --field 电影 --client 自家 --topic 雨夜重逢 --date 2026-10-20 \
  --title 雨夜重逢 --tags "短片, 雨夜" --tool Seedance \
  --source ~/Desktop/创作与运营项目/电影创作/4-影片/P20261020-雨夜重逢 \
  --final 成片.mp4 --cover 封面.jpg --prompt 提示词.md --record 制作记录.md \
  --version 第一版文件夹 --version 第二版文件夹 --extra 分镜.pdf
```

- `--final` 成片或成图，可写多次；视频名里没有「成片 / 发布版 / 母版」会自动加上 `成片_` 前缀。没给 `--cover` 就用第一张成图当封面。
- `--version` 一个版本一个文件夹，按顺序存成 `V1`、`V2`…，作品里已有版本就接着往后编号。
- `--prompt` 存成 `提示词.md`（多份就 `提示词-1.md`…），`--record` 第一份存成 `记录.md`，`--extra` 放进 `资料/`。
- 先加 `--dry-run` 看会做什么；重复运行是安全的，已经收过的文件会跳过。
- 收完会自动刷新索引，输出 JSON 列出复制、跳过、重名的文件。

## 导出

```sh
spt/bin/spt export --format xlsx            # 全部，一张总表
spt/bin/spt export --format csv --kind prompt
```

文件写到 `spt/server/.cache/exports/`，命令会打印路径。xlsx 有「全部」页、每种类型各一页和「数据」页（一行一次数据记录）；`--kind metrics` 只导出数据记录。作品的旧版本提示词和列表一样默认不导出，要的话加 `--all-versions`。

## 规矩

- 2026-10-23 本机新增授权发布队列：已收录作品从详情「发布」带入；仅在 用户的当前明确授权范围内入队，复用原账号会话和官方控件。按账号串行、不同账号限流并发；未知结果先回查，不再点击。结果和证据写回原作品，不再导入或搬动媒体。下条「SPT 只读，不发布」描述资产库默认行为，队列仅按此项明确授权例外执行。未接入的平台保留原手动入口；不得宣称历史笔记或互动数据自动全量同步。

- SPT 只读，不发布。会写文件的只有：「便签」页、工作区位置设置、「整理客户」（重写 `客户.md`）、`spt add`（只新增）、`spt metrics add / retention / analyse / account`（只追加，不改旧行）；界面里的删除（便签、作品文件夹）只移进系统废纸篓。发布、提交表单、对外发消息，必须 用户 本人确认后再做。
- 账号、密码、cookie、token、身份证件不放进这个库。
- 删除走系统废纸篓，不用 `rm`。
- 代码要同时能在 Mac 和 Windows 上跑：不写只有 Mac 才有的调用（`sips`、`cp -c`、`fcntl`、`/usr/bin/open`、`os.O_NOFOLLOW` 等），非用不可就同时写好 Windows 的退路；路径用 `Path`，文字文件都写明 `encoding="utf-8"`。
- 改作品就开新版本，不覆盖旧版本。
- 写完文件记得刷新索引；如果 SPT 显示「未能读取」，到「设置 › 资产库」看是哪个文件。
